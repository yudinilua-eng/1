# Патч v4 для образовательной платформы

## Что изменено

- ЛК преподавателя стал устойчивее: один упавший запрос Supabase больше не ломает весь кабинет.
- Убраны вложенные Supabase-запросы, которые часто давали `400 Bad Request` при несовпадении foreign key-связей.
- Данные теперь догружаются простыми запросами `select('*')`, а связи ученик/тема/тип занятия собираются в браузере.
- Починен `toggleLessonType`: кнопки «Скрыть / Включить» больше не вызывают код слотов с несуществующей переменной `status`.
- Улучшен `setSlotStatus`: обновляет статус, пишет в activity log, ставит событие в `google_sync_events`, списывает занятие из пакета при статусе `completed`.
- Исправлено сохранение материалов из нового ЛК: используется поле `file_url`, а не несуществующее `url`.
- Добавлены обработчики изменения и удаления ученика в новом функциональном ЛК.
- Добавлен SQL `supabase_platform_optimization_v4.sql` с недостающими колонками, индексами, очередями уведомлений и Google sync.

## Как обновить

1. Замените файлы проекта в GitHub на файлы из архива.
2. Сделайте commit.
3. Дождитесь нового deployment в Vercel.
4. В Supabase откройте SQL Editor и выполните файл:

```sql
supabase_platform_optimization_v4.sql
```

5. Очистите кэш сайта: `Cmd/Ctrl + Shift + R`.
6. Проверьте разделы:
   - ЛК преподавателя → Ученики
   - ЛК преподавателя → Расписание
   - ЛК преподавателя → Финансы
   - ЛК преподавателя → Домашние задания
   - Публичная страница записи

## Важно про Google

Сайт теперь создаёт события в таблице `google_sync_events`. Это правильный безопасный слой. Реальная отправка в Google Calendar / Sheets / Drive должна выполняться серверной Supabase Edge Function `process-google-sync`, где подключаются Google OAuth или Service Account. Ключи Google нельзя хранить в браузерном `index.html`.
